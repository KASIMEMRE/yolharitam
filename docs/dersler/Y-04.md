# Y-04 · Adımları oluşturma — Ders notu

## Bu PR'da ne değişti?
Kullanıcı artık konu ve seviyeyi seçtikten sonra 3 kısa soru yanıtlıyor (haftalık süre, hedef, öğrenme tarzı). Bu cevaplara göre uygulama 6-8 adımlık kişisel bir yol haritası üretiyor. Üretici bir **saf fonksiyon**: aynı girdi verirsen hep aynı çıktıyı verir, internete ya da ekrana ihtiyaç duymaz. Sonuç, **RPC** ile (veritabanında çalışan bir fonksiyonu uygulamadan çağırmak) tek seferde Supabase'e yazılıyor. Ekranlar arası geçişi de Expo Router yönetiyor.

## Kavramlar

### 1. Saf fonksiyon + veri tablosu, ve "aynı imza, değiştirilebilir üretici"
- Ne: Saf fonksiyon, tarif gibidir. Aynı malzemeyi verirsen aynı yemek çıkar, mutfağın dışında hiçbir şeye dokunmaz. Kuralları `if/else` yığını yerine bir tabloya (veri) yazarsan, kuralı değiştirmek için kod okumana gerek kalmaz, tabloya bakarsın.
- Bizim kodda: `src/constants/roadmap-templates.ts:52-57`
  ```ts
  export const HOURS_RULES: Record<WeeklyHoursId, { weekly: number; multiplier: number }> = {
    '1-2': { weekly: 2, multiplier: 0.75 },
    '3-5': { weekly: 4, multiplier: 1 },
    '6-10': { weekly: 8, multiplier: 1.25 },
    '10+': { weekly: 12, multiplier: 1.5 },
  };
  ```
  `weekly` özet hesabında kullanılan haftalık saat, `multiplier` adım büyüklüğü çarpanı. Çarpan `:255`'te kullanılıyor: `Math.round(template.baseHours * multiplier)`.
  Asıl numara `:265-270`'te: `generateRoadmapSteps` bugün sadece `generateTemplateSteps`'i çağırıyor, ama **asenkron** tanımlı. Y-06'da içine yapay zekâ çağrısı gelecek (hata verirse şablona düşülecek). İmza aynı kaldığı için ekran kodu (`roadmap-questions.tsx:219`) hiç değişmeyecek. `validateSteps` (`:274`) de çıktıyı kaydetmeden önce doğruluyor; yapay zekâ çıktısı da aynı sözleşmeye uymak zorunda olacak.
- Yaygın hata: Üreticiye `supabase` ya da `Date.now()` / `Math.random()` gibi şeyler karıştırmak. O an fonksiyon saf olmaktan çıkar, test etmek ve sonucu tahmin etmek zorlaşır. Dosyanın başındaki "içe aktarma yok" kuralı (`:3`) bunu önlüyor.

### 2. Postgres fonksiyonu (RPC) ile atomik kayıt; RLS, `security invoker`, hata kodları
- Ne: Bir havale düşün: para bir hesaptan çıkıp diğerine girmezse işlem hiç olmamış sayılmalı. **Atomik** = ya hepsi olur ya hiçbiri. Yol haritasını ve adımlarını iki ayrı istekle yazsaydık, arada internet kopunca "yol haritası var, adımı yok" yarım kaydı kalabilirdi.
- Bizim kodda: `supabase/migrations/20261019160000_roadmap_steps.sql:187-198` ve `:204-211`
  ```sql
  create function public.create_roadmap_with_steps(...)
  returns uuid
  language plpgsql
  security invoker
  set search_path = ''
  ...
    insert into public.roadmaps (user_id, topic_path, level)
    values ((select auth.uid()), p_topic_path, p_level)
    returning id into v_roadmap_id;
    perform public.add_steps_to_roadmap(v_roadmap_id, ...);
  ```
  - `security invoker`: fonksiyon, çağıran kullanıcının yetkisiyle çalışır. Yani RLS (satır bazlı güvenlik) politikaları aynen geçerli, kimse başkasının verisine yazamaz.
  - `auth.uid()`: `user_id`'yi istemciden almıyoruz, oturumdan okuyoruz. İstemciye güvenilmez.
  - `unique (roadmap_id, position)` (`:34`): adımlar zaten yazılmışsa `23505` hatası döner; fonksiyon tek işlem olduğu için yazılan güncelleme de geri alınır (`:172-173`).

  İstemci tarafı `src/app/roadmap-questions.tsx:238-257`'de `supabase.rpc('create_roadmap_with_steps', {...})` çağırıyor; hata kodu `:266-268`'de okunuyor:
  ```ts
  const kind = classifyError(rpcError);
  if (kind === 'duplicate' && roadmapId) return 'exists';
  ```
  `23505` hata değil, "zaten hazır" demek; kullanıcıya kırmızı hata göstermeyiz.
  **Boş sonuç ≠ hata** ilkesi `src/hooks/use-roadmap-steps.ts:10-13`'te yazılı: `ready` + boş liste "henüz adım yok", `schema/network/error` ise "okuyamadık" demek. Karıştırırsak hata anında kullanıcıya "Adımlarını oluşturalım" gösterirdik. Kod bunu `:40-49`'da ayırıyor: hata varsa `steps: []` ile birlikte hata durumu, yoksa `status: 'ready'`.
- Yaygın hata: `error` kontrol etmeden `data ?? []` ile devam etmek. Ağ düşse bile liste boş görünür ve uygulama yanlış bir şey söyler.

### 3. Expo Router yığını: `push`, `dismissAll`, `navigate` ve route parametreleri
- Ne: Ekranlar bir tabak yığını gibi üst üste dizilir. `push` üste yeni tabak koyar, `dismissAll` yığındaki tüm tabakları kaldırır, `navigate` ise ilgili ekrana gider (zaten varsa yenisini eklemek yerine ona döner).
- Bizim kodda: Soru ekranı seviye sayfasından açılıyor: `src/app/onboarding.tsx:53`
  ```ts
  router.push({ pathname: '/roadmap-questions', params: { topicPath: path.join('/'), level } });
  ```
  Yol haritası sekmesinden (adımsız eski kayıt için) ise `roadmapId` parametresiyle açılıyor: `src/app/(tabs)/roadmap.tsx:244`. Hedef ekran parametreleri `roadmap-questions.tsx:74`'te okuyor:
  ```ts
  const params = useLocalSearchParams<{ topicPath?: string; level?: string; roadmapId?: string }>();
  ```
  Bitince `:205-208`:
  ```ts
  router.dismissAll();
  router.navigate('/roadmap');
  ```
  Önce yığın temizlenir, sonra Yol Haritam sekmesine gidilir. Yalnız `back()` yapsaydık kullanıcı seviye sayfasında kalırdı.
  Ayrıca parametreler **her zaman metin** gelir ve opsiyoneldir (`?`); bu yüzden `persist` başında `if (!topicPath || !level)` kontrolü var (`:214`).
- Yaygın hata: Parametreleri sayı ya da zorunlu sanmak; ya da her yerde `router.back()` kullanıp yığın derinleşince kullanıcıyı yanlış ekrana düşürmek.

## Kendin dene (10-15 dk)
`src/constants/roadmap-templates.ts:55`'teki `'3-5'` satırında `multiplier: 1` değerini `1.5` yap. Sonra uygulamayı aç, yeni bir konu seç (Başlangıç seviyesi), sorularda **3-5 saat**, **İş bulmak**, **Karışık** seç.
Telefonda kutlama ekranında şunu görmelisin: **8 adım · yaklaşık 44 saat · yaklaşık 11 hafta**. Değişiklikten önce aynı seçimlerle **28 saat, 7 hafta** çıkardı. Bittikten sonra değeri `1`'e geri al.

Neden böyle oldu? Adım saatlerinden birinin (`3 × 1.5 = 4.5`) tam sayı çıkmadığını fark ettin mi? Sonuç neden 4.5 değil de tam sayı? Ve haftayı bulmak için neden toplam saatin `weekly` ile bölümü yukarı yuvarlanıyor?

<details>
<summary>Cevap</summary>

Her adımın saati `Math.round` ile yuvarlanır (`:255`), yani 4.5 → 5. Veritabanında `estimated_hours integer` (`.sql:29`) ve `validateSteps` de tam sayı istiyor (`:283`), yani 4.5 kaydedilemezdi. Kutlamadaki sayı için: 3 temel adım 5×3 = 15, 2 pratik adım 6×2 = 12, hedef adımları 3 + 9 + 5 = 17; toplam 44 saat. Hafta sayısı `Math.ceil(44 / 4) = 11`: 10,5 haftalık iş de 11. haftaya taşar, kimse "yarım haftada" bitirmiş sayılmaz. `Math.max(1, ...)` (`:297`) en az 1 hafta olmasını da garanti eder.
